# コンソール UI（`/ui/`）ブラウザ手動スモーク観点

`holter-http-api` に埋め込まれた簡易コンソールの**手動確認観点**です。実ブラウザと実ライセンス環境に依存するため、**初期 CI 必須にはしません**。

関連: 配布導入ドキュメント（[docs/packaging/](./packaging/)）、自動検証は `src/http/routes.rs` / `static_ui.rs` のユニットテスト。

## 前提

- [ ] `holter-http-api` が起動し、ブラウザから `http://<host>:<port>/ui/` に到達できる
- [ ] ライセンス設定（`[license] server_url` 等）が疎通可能な環境を指している
- [ ] 追加のフロントエンドサーバーや別 UI 成果物は不要（同一バイナリ配信）
- [ ] 画面は左約 1/3 が入力・右約 2/3 が出力、右上にヘルス表示（Bulma）

## 確認観点

1. **ヘルス自動表示（右上・ボタンなし）**
   - [ ] `/ui/` を開くと右上にヘルス状態が控え目に表示される
   - [ ] 約 10 秒おきに更新される（手動ボタンはない）
   - [ ] ヘルス確認だけでは利用計上が増えないこと（運用上の期待。自動テストで非計上を検証済み）

2. **未選択エラー**
   - [ ] ECL を選ばずに解析実行すると、リクエストを送らず日本語で不足が示される

3. **小入力での解析成功 → 表示 → ダウンロード**
   - [ ] 出力形式の既定が **JSON** である
   - [ ] 小さな有効 ECL（またはフィクスチャ）で解析が成功する
   - [ ] 結果が右側の出力領域で確認できる
   - [ ] ダウンロード手段で結果をローカル保存できる
4. **失敗時（任意）**
   - [ ] 故意の失敗（空ファイル等）で解析成功扱いにならず、日本語で失敗が分かる

## 範囲外

- SPA e2e フレームワーク必須化
- ライセンスサーバー実機を CI ゲートに含めること
- 臨床判定・波形・帳票 UI
