# Brief: license-client

## Problem

推論の利用回数を把握・制御できないと、商用ライセンス運用ができない。  
ライセンスサーバーは別プロジェクトで用意するため、本製品側はクライアントと設定だけを持つ必要がある。

## Current State

- 解析はローカル完結で、外部ライセンス連携なし
- 設定ファイル（ini）による外部サービス接続は未整備

## Desired Outcome

- プロセス起動時に 1 回、ライセンス有効性を確認する（失敗時は起動拒否）
- **1 推論（= 1 解析ジョブ）ごと**に 1 回、許可確認と利用計上を行う（失敗時はその推論を拒否）
- ライセンスサーバーのエンドポイント等は **ini ファイル**で設定できる
- サーバー本体・課金 DB・管理 UI は本リポの範囲外

## Approach

`reqwest`（または同等）でライセンスサーバー HTTP API を呼ぶ薄いクライアントを `lib` に置く。  
CLI / 将来 API の双方が同じゲートを通る。サーバー契約（パス・認証・レスポンス）は別プロジェクトと合意し、本仕様ではクライアント側の振る舞いと設定項目を定義する。開発時はモック／スタブで進められるようにする。

## Scope

- **In**:
  - 起動時チェック / 推論時チェック＋計上
  - ini 設定（少なくともサーバー URL。必要に応じ API キー・タイムアウト等）
  - 失敗時の明確なエラー（起動失敗 / 推論拒否）
  - 単体テスト可能なモック境界
- **Out**:
  - ライセンスサーバー実装
  - 課金・請求・管理画面
  - window 単位の都度課金（ fullday で数千回になり運用不能）

## Boundary Candidates

- 設定読込（ini）
- ライセンス HTTP クライアント
- 解析エントリへのゲート挿入点

## Out of Boundary

- モデル埋め込み
- HTTP API のリソース設計（ゲート呼び出し位置のみ共有）
- 配布パッケージ

## Upstream / Downstream

- **Upstream**: 別リポのライセンスサーバー契約（URL / 認証 / レスポンス）
- **Downstream**: `http-api`（起動時・リクエスト時ゲート）, CLI

## Existing Spec Touchpoints

- **Extends**: none
- **Adjacent**: `model-embedding`（並行可能。API 前に両方完了が望ましい）

## Constraints

- 「1 推論」= `analyze-ecl` 相当の 1 ジョブ、または API の 1 解析リクエスト。ONNX の 1 window ではない
- オフライン運用は初期対象外（サーバー到達必須）
- 秘密情報を ini に置く場合の取り扱い（権限・ログマスク）を requirements で明示
- Windows / Linux 双方で同一設定キー
