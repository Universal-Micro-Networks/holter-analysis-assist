# Implementation Plan

- [x] 1. Foundation: 依存追加とライセンス型の骨格
- [x] 1.1 ライセンスクライアント用の依存クレートを追加する
  - blocking HTTP クライアント（reqwest 0.12 系）と ini パーサをプロジェクト依存に追加する
  - MSRV 1.74 を満たすバージョン選定であることをビルド解決で確認する
  - 完了条件: `cargo check` が新依存込みで成功する

- [x] 1.2 起動失敗・推論拒否を区別するエラー型と最小応答型を定義する
  - 有効性確認結果・計上結果・設定不正を含む区分付きエラーを用意する
  - エラー表示に秘密情報の平文が含まれないことを型側の方針として固定する
  - 完了条件: ライセンス用モジュールがライブラリから公開され、区分付きエラーをコンパイルできる
  - _Boundary: LicenseTypes_
  - _Requirements: 5.1, 5.2, 5.3, 7.1_

- [x] 2. Core: 設定読取とクライアント境界
- [x] 2.1 (P) ini からライセンス接続設定を読み取り検証する
  - セクションとキー（少なくともサーバー URL。任意で認証・タイムアウト・パス）を Win/Linux 同一名で読み取る
  - 必須欠落・不正値は fail-closed となる設定エラーにする
  - 認証情報のデバッグ表示をマスクし、**本仕様所有の正本** `config/license.ini.example` に `[license]` とファイル権限の運用注記を含める
  - 完了条件: 正当な ini から設定を構築でき、必須欠落時は明確な設定エラーになる。サンプル ini がリポジトリに存在し `[license]` 正本として文書化されている
  - _Boundary: LicenseIniConfig_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 7.1, 7.2, 7.3_

- [x] 2.2 (P) 差し替え可能なライセンスクライアント境界とテスト用モックを用意する
  - 有効性確認と許可+計上の 2 操作をポートとして定義する
  - 成功・拒否・通信失敗を外部到達なしで再現できるモックを用意する
  - 完了条件: モック実装だけで両操作の成功/失敗パターンを単体で呼び分けられる
  - _Boundary: LicenseClient_
  - _Requirements: 6.1, 6.2, 6.3_

- [x] 3. Core: HTTP 実装とゲート API
- [x] 3.1 (P) ライセンスサーバー向け HTTP アダプタを実装する
  - 設定の URL・パス・タイムアウト・任意 API キーで有効性確認と許可+計上を呼ぶ
  - 非許可・非成功応答・タイムアウト・輸送失敗をすべて失敗として返す
  - ログおよびエラーに API キー平文を出さない
  - 完了条件: モック HTTP または同等手段で成功/拒否/失敗を再現でき、ポート実装としてゲートから利用可能
  - _Boundary: ReqwestLicenseClient_
  - _Depends: 2.1, 2.2_
  - _Requirements: 1.1, 2.1, 7.1, 7.3, 8.1_

- [x] 3.2 (P) 起動時確認と推論時確認のゲート API と process-wide install を実装する
  - 起動用ゲートは有効性確認のみ、推論用ゲートは許可+計上を行い、失敗時は続行しない
  - `install` / `global` / `try_global` を提供し、未 install 時の推論経路は fail-closed
  - オフライン継続や握りつぶし経路を設けない
  - 完了条件: モッククライアント接続時、拒否/失敗で Ok が返らず、成功時のみ Ok になる。未 install でも推論が通らない
  - _Boundary: LicenseGate_
  - _Depends: 2.2_
  - _Requirements: 1.2, 1.3, 2.2, 2.3, 5.1, 5.2, 5.3, 8.1, 8.2, 9.1, 9.2, 9.3_

- [ ] 4. Integration: 解析入口とプロセス起動への配線
- [x] 4.1 正本入口 `analyze_ecl_with_source` で許可確認と利用計上を 1 回だけ行う
  - model-embedding による `ModelSource` 配線の後に、本仕様が `src/analyze.rs` へゲートを挿入する
  - meter / `ensure_inference_allowed` は正本入口先頭のみ。`analyze_ecl` / `analyze_ecl_with_limit` には追加しない（二重計上禁止）
  - Gate は `global` / `try_global` で取得（解析シグネチャに Gate 引数を足さない）
  - ゲート失敗時は解析結果を出力しない。ONNX window デバッグ経路には計上ゲートを入れない
  - HTTP API リソース設計・配布成果物・ModelSource 定義には手を入れない
  - 完了条件: モック計上成功でジョブが続行し、失敗で出力が作られず、ラッパ経由・複数 window でも計上が合計 1 回である
  - _Boundary: AnalyzeEntryIntegration, LicenseGate_
  - _Depends: 3.2_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 3.4, 5.2, 5.3, 8.3, 9.2, 9.3_

- [ ] 4.2 プロセス起動時に Gate を install し有効性確認を行い失敗時は起動を拒否する
  - CLI `src/main.rs`（本仕様所有）でサブコマンド実行前に設定読取 → install → 起動ゲートを適用する
  - 失敗時は起動失敗として識別可能なメッセージで非 0 終了し、解析を開始しない
  - HTTP main も同一 install 契約を使うことを Cross-Spec Contracts どおり隣接仕様に委ねる（本タスクは CLI 側）
  - ライセンスサーバー本体や配布パッケージの追加は行わない
  - 完了条件: 起動確認失敗時に解析サブコマンドが実行されず、成功時のみ既存サブコマンドが動く。install 後に正本入口が global を参照できる
  - _Boundary: CliStartupIntegration, LicenseGate_
  - _Depends: 3.2, 2.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 4.4, 5.1, 5.3, 8.2, 8.3, 9.1, 9.4_
